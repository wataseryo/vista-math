# 問題・単元の追加と公開前確認

2026-10-12。現在は静的HTMLと分割JavaScriptの教材を配信する構成です。サーバーDB・認証・クラウド同期はありません。

## 既存単元へ追加

1. `data/problems/practice-*.js` または `challenge-*.js` の対象単元へ追加します。`data/problems.js` へ問題本文を直接書きません。
2. IDは全問題を通じて一意にし、一度公開したIDを別問題に再利用しません。学習記録がIDに結び付いています。分類・題名の修正だけならIDを維持します。
3. `grade`は5/6、`difficulty`は1〜5の整数、`answer`は有限の数値、`answerUnit`は文字列です。題名・問題文・ヒントを必ず用意します。
4. 演習は`course`（`std`/`exam`）、`answerType:'number'`、`solution`が必須です。受験演習は`catId`、標準演習は`chapterId`を対応する定義に合わせます。`mainCategory`は`CATEGORIES`の正規IDを使います。
5. 関連トピックがある場合は`topicUnitId`を明示します。食塩水なら`u6-salt`であり、これにより一般の割合教材への誤遷移を防ぎます。
6. 演習解説は最低2つの`【】`見出し、丸数字の手順、`【確認】`、最後の`答え：`を含めます。難問は`categoryLabel`と、`title`/`text`を持つ`explanation`配列を指定します。

## 解説の質の基準（2026-10-15 ユーザー指示で追加）

単に手順を並べるだけでなく、1問から何かしら学べる解説にする。新規に書く演習問題は以下を満たす。

1. **「なぜ」を書く**: 手順の中に、その計算・解法を選ぶ理由を明示する丸数字ステップを1つ以上入れる（例:「なぜかけ算を先にするのか」「なぜ最小公倍数を使うのか」）。公式や手順を結果だけ示さない。
2. **【広げてみよう】を入れる**: 手順と【確認】の間かその前後に`【広げてみよう】`という見出しを追加し、この問題で使った考え方が他の場面でも使えることを具体的に書く。可能なら別の単元・別のタイプへの橋渡し（例:「この最小公倍数の考え方は通分にも体積の水そう問題にも使える」）を入れる。単なる豆知識ではなく、他の問題に転用できる気づきにする。
3. 色付けなどのリッチな装飾は現状レンダラーが`solution`文字列をHTMLエスケープして表示するため使えない（`js/app.js`の`renderSolutionSteps`参照）。強調したい場合は見出し（`【】`）か文章の工夫で表現する。色付けが必要な場合はレンダラー側の対応（Codexへの実装依頼）が別途必要。
4. この基準は2026-10-15以降に新規作成する演習問題に適用する。既存問題への遡及適用は別途指示があるまで行わない。

## 新しい分割ファイル・単元

- 分割ファイルで定数配列を宣言し、`data/problems.js`の対応する結合配列へ加えます。
- `index.html`で分割ファイルを集約ファイルより前に読み込みます。`js/catalog.js`は集約後、`js/app.js`より前に読み込みます。
- `data/categories.js`へ対象学年の単元と演習カテゴリを追加し、公開可能な学習画面は`topicScreen`で明示します。標準章は全て水槽へ飛ぶ仕組みではありません。`available:true`にする前に、正しい画面が存在することを確認します。
- 手入力`count`を表示の根拠にしません。受験単元のチャレンジ件数は`VistaCatalog.unitCount(grade,unitId)`、演習件数は`VistaCatalog.practice(grade,course,categoryId).length`で取得します。チャレンジと演習を合算する場合は重複の扱いを別途明確にします。
- `categories`はチャレンジの`categoryLabel`に対応します。下位単元を親と重複集計した数を「全体のユニーク問題数」と表示しないでください。
- 標準教材は`VistaCatalog.standardTopic`、問題の関連教材は`VistaCatalog.problemTopic`で判定します。教材がない場合はリンクを出しません。


検証は全問題のID・学年・分類・参照・正答値の型・説明の存在、分割ファイル読込と集約漏れをチェックします。エラーはファイル・問題ID・原因を表示して終了コード1になります。旧来の解説書式は警告として数えます。既存75問の書式警告を今回自動修正していません。該当問題を編集する際に新書式へ揃えてください。

**構造検証は数学的な正解・解説の正しさを証明しません。** 追加問題は別解・逆算を行い、図と数値の一致、学年・難易度、関連教材、スマートフォン表示を独立レビューします。公開前に学年→コース→単元→問題→関連教材→元問題の往復、再読込、保存も確認します。

## 学習記録の運用制約（2026-10-12 11:37 BST）

問題ごとの正誤履歴は全件を保持します。表示は最新10件に絞りますが、保管データを勝手に切り捨てることはありません。長期間・多数の解答では、保存容量と毎回の記録処理量が増加します。保存はブラウザの容量に依存するため、無期限・無制限の保管は保証できません。

保護者・運営者は定期的に「学習記録・バックアップ」からファイルを保存してください。「このブラウザに保存できません」という警告が出た場合は、その画面を閉じたり再読込したりする前に、すぐバックアップしてください。保存に失敗した記録はそのタブのメモリ内にだけ残っている場合があります。複数タブの競合警告でも、当該タブのバックアップを保存してから再読込します。複数タブ分の自動合算はありません。

将来の履歴圧縮は、全期間の解答/正答集計と直近履歴・最終正誤/日時を分離する案があります。ただし、既存の苦手分析・レポート・復元との整合性、バックアップ形式の移行、原データの保護が必要です。今回の更新では実施していません。
