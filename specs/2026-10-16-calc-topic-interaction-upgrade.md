# 製品仕様書: 計算トピック画面インタラクションのアップグレード

発注元: ユーザーが別デモ(Artifact「くふうラボ」、VISTA外のプロトタイプ)で検証した3つのUIアイデアのうち、2つを採用。VISTA本体(`u6-calc-screen`)に組み込む。

## 背景

`specs/2026-10-16-calc-topic-screen.md`で実装した計算トピック画面の「基本例題」セクションは、3つの選択肢ボタン(25×13 / 25×4 / 13×4)から選ぶだけの簡易な予測インタラクションだった。ユーザーがVISTA外で試作したデモをレビューした結果、以下を正式採用する。

1. **ペア探しミニパズル+発見のご褒美**: 3つの数字をタップで選び、その場で積が表示される。きれいな数(100)に気づいたら軽い演出(キャラの反応+ひとこと)が出る。きれいでない組み合わせを選んでも怒らず、優しく再挑戦を促す。
2. **「大変さ」のビフォーアフター**: 速さを競わせるのではなく、同じ人が同じ2stepを解いた場合の「頭の疲れ方」の違いを、ふつう(🏋️重い)→くふう(🪶軽い)の順に見せる。時間は測定・比較しない。

採用しなかったもの(実装しない): 「ふつう vs くふう」の2レーン競走形式(計算する人によって時間が変わり基準があいまいという理由で不採用)、恒久的なバッジ・コレクション機能(実装負荷が高い割に効果が不明という理由で不採用)。

参考実装(挙動の参考用。見た目はVISTAの既存デザインに合わせて作り直すこと。デモの配色・フォント・「チョークボード」風の装飾は踏襲しない):

```
3つの数字タイル(25, 13, 4)をタップで選択(最大2つ)
→ 選んだ2つの積をその場でプレビュー表示
→ 積が100(25×4)なら: タイルが合体するアニメーション→キャラ反応+ひとこと+軽いきらめき演出→残りの計算(100×13=1300)を表示
→ 積が100以外(325 or 52)なら: 「◯◯…うーん、きれいな数じゃないね。他の組み合わせも試してみよう」と表示、ペナルティなしで再選択可能
```

```
「ふつうに解くと…」パネルが先に表示され、①②のステップが少し間を置いてゆっくり現れる(🏋️アイコン)
→ 少し間を置いて「くふうすると…」パネルが表示され、①②のステップが素早く現れる(🪶アイコン)
→ 最後に「同じ2stepでも、頭の中の大変さはぜんぜん違う」という一言
```

## 完了条件

- [x] `index.html`の`u6-calc-screen`内、現在の「基本例題」セクション(3択ボタン方式の予測インタラクション)を、ペア探し方式(3つの数字タイルをタップして選ぶ、積をプレビュー、正解で軽い演出、不正解で優しい再挑戦誘導)に置き換える
- [x] 正解時の演出は「恒久的な記録を残さない、その場限りの軽い演出」とする(キャラクター絵文字の反応アニメーション+短いひとこと+きらめき程度。新しいデータ保存・コレクション機能は作らない)
- [x] 「6. 基本例題」セクションの後(または適切な位置)に、新しいセクション「大変さのビフォーアフター」を追加する。既存の7セクション構成(学ぶこと/入試での出方/見分け方/使う図/よくあるミス/基本例題/演習導線)の順序・内容は変更しない。体験問題セクション・演習導線より前に配置する。
- [x] ビフォーアフターセクションは、時間を測定・表示しない(数値的な速さ比較はしない)。「ふつう」→(間を置いて)「くふう」の順に、ステップの出現速度の違いで「大変さ」の違いを表現する
- [x] 見た目(色・フォント・カードのスタイル)は、既存の`u6-calc-screen`・`css/calc-topic.css`・`topic-example-card`/`topic-steps`等の既存クラスやトーンに合わせる。デモ特有の配色・フォント(Yomogi/DotGothic16等)は使わない
- [x] `prefers-reduced-motion`に対応する(既存の予測インタラクション実装と同様の配慮を踏襲)
- [x] キーボード操作・フォーカス可視化など、既存のアクセシビリティ水準を落とさない
- [x] `node scripts/validate-content.cjs`が0エラーで通過する
- [x] `npm test`が全件passする
- [x] 実ブラウザで以下を確認する: 3つの数字タイルをタップして積がプレビューされる、正解(25×4)で演出が出て100×13=1300まで進む、不正解(25×13または13×4)を選んでも優しい再挑戦メッセージが出て再選択できる、「もう一度見る」でリセットできる、ビフォーアフターセクションが時間表示なしで「ふつう→くふう」の順に表示される、既存の7セクション・体験問題・演習導線に影響がない(Claude環境でdesktop/mobile両方確認、`sprints/calc-topic-interaction-upgrade/sprint-1-eval-claude.md`参照)
- [x] 平面図形(u6-plane)・他の未実装単元・計算の既存演習9問の`text`/`solution`に意図しない変更がない

## 制約・前提条件

- 平面図形(u6-plane)は対象外。既存実装への変更は一切行わない。
- 既存の演習問題9問(`practice-g6-calc.js`)の内容は変更しない(本スプリントの対象外)。
- `data/categories.js`は変更不要(今回は`u6-calc-screen`内部の実装のみ)。
- 今回採用した2つのインタラクションパターン(ペア探し+ご褒美演出、大変さのビフォーアフター)は、今後他単元のトピック画面(数の性質・場合の数・立体図形・変化グラフ等)でも再利用できる形で実装することが望ましい(関数名・CSSクラス名を`u6-calc`専用にせず、他単元でも呼び出しやすい汎用的な設計を検討する。ただし本スプリントでは計算のみに適用し、他単元への展開は別スプリントで行う)。
