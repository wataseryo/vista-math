# 製品仕様書: 体験問題セクション UX 改善

## プロダクト概要

トピック画面内の体験問題セクション（`trial-*` セクション）の UX を 3 点改善する。
対象ファイルは `js/app.js`（`checkTrialAnswer` / `generateChoices` 関数）と `css/style.css`。
小学 5・6 年生が自力で考える余地を持てるよう、不正解時にすぐ答えを見せない設計に変える。

## 機能一覧

| # | 機能名 | 概要 | 優先度 | スプリント |
|---|--------|------|--------|-----------|
| 1 | 不正解時の段階的フィードバック | 不正解後は「もう一度考えてみよう」のみ表示し、「答えを確認する」ボタン押下後に正解・解説を表示する | Must | 1 |
| 2 | 不正解時の正解ボタンハイライト遅延 | 「答えを確認する」押下後に正解ボタンを緑ハイライトする（押下前は押し間違えボタンを赤のまま維持） | Must | 1 |
| 3 | ダミー選択肢の差分スケール修正 | 数値 answer のダミー生成差分を正解値の 10〜30% 程度に抑え、現実的な選択肢範囲にする | Must | 1 |

## スプリント計画

### Sprint 1: 体験問題 UX 改善（全 3 点）

- 機能: 不正解時の段階的フィードバック、正解ハイライト遅延、ダミー差分スケール修正

- 完了条件:
  - [ ] 不正解の選択肢を選んだとき、「惜しい！もう一度考えてみよう」というメッセージのみ表示され、正解値・解説は表示されない
  - [ ] 不正解後に「答えを確認する」ボタンが表示される
  - [ ] 「答えを確認する」を押すと、正解値・解説が表示される
  - [ ] 「答えを確認する」を押すと、正解の選択肢ボタンが緑（`.correct` クラス）でハイライトされる
  - [ ] 「答えを確認する」を押す前は正解ボタンがハイライトされず、押し間違えたボタンだけ赤（`.wrong` クラス）になっている
  - [ ] 正解を選んだとき、従来通り即座に正解メッセージ・解説が表示される（変更なし）
  - [ ] 「次の問題へ」ボタンは「答えを確認する」を押す前でも押せる（スキップ可能）
  - [ ] 数値 answer のダミー選択肢が、正解値の 10〜30% 程度の差分で生成される（例: 正解 200 のとき差分は 20〜60 程度）
  - [ ] ダミー候補から負の値が除外される
  - [ ] 文字列 answer の選択肢生成は従来通り変わらない
  - [ ] スマホで各選択肢ボタンのタップ領域が維持される（`padding` 等を変更しない）

## 制約・前提条件

- `index.html` 1 ファイル構成を維持する（`js/app.js` / `css/style.css` は別ファイルとして存在するため、それらも直接編集してよい）
- `openUnitPractice` 関数・画面遷移ロジックは変更しない
- 正解選択時のフロー（即時解説表示）は変更しない
- 既存 CSS クラス `.correct` / `.wrong` / `.topic-trial-feedback.ok` / `.topic-trial-feedback.ng` のスタイル定義はそのまま流用する
- 「答えを確認する」ボタンの新規スタイルは `css/style.css` の体験問題セクション内（`.topic-trial-next-btn` の近辺）に追記する
- 答えは必ず整数（問題データ側の前提。ダミー生成時も整数値を維持する）

## 実装対象の関数・処理の現状メモ（仮定含む）

### `checkTrialAnswer`（`js/app.js` 1887 行付近）

現状:
- 不正解時、選んだボタンに `.wrong`、正解ボタンに `.correct` を即付与する（1906 行）
- `feedbackEl` に正解値・解説を含む HTML を即 `display:block` する（1922 行）

修正後に変えるべき点:
- 不正解時は正解ボタンへの `.correct` 付与をスキップする
- `feedbackEl` の内容を「惜しい！もう一度考えてみよう」のみにし、正解値・解説は含めない
- 「答えを確認する」ボタンを `nextEl` または新規要素として追加する
- 「答えを確認する」を押す関数（例: `revealTrialAnswer`）を新設し、正解ボタンへの `.correct` 付与と正解値・解説の表示をそこで行う

### `generateChoices`（`js/app.js` 1833 行付近）

現状:
- `step = Math.max(1, Math.round(Math.abs(base) * 0.25) || 1)` で 25% を基準値とし、
  `base ± step`, `base ± step*2`, `base ± step*3`, `base ± 1`, `base ± 2`, `base ± 3` を候補にしている
- 大きい数値（例: base=200 なら step=50、最大差分=150）で選択肢が広がりすぎる

修正後:
- 差分を `Math.round(base * (0.1 + Math.random() * 0.2))` のような 10〜30% ランダム範囲に変更する
- ダミー 3 件が確保できるよう候補を複数用意し、重複・負値を除外する
- 差分が小さすぎて候補が足りなくなるケース（base が 1〜3 程度の極小値）では最低差分 1 を保証する

## 未解決の仮定

- 「答えを確認する」ボタンのデザインは `topic-trial-next-btn` に近いスタイル（幅 100%、角丸、ファミリー統一）を想定しているが、色は「次の問題へ」と区別するためニュートラル系（例: グレー系またはアウトライン）にすることを仮定している。Generator が判断してよい。
- `trialState` に `revealedAnswer` フラグを追加して「答えを確認する」押下済みかを管理することを想定しているが、実装方法は Generator に委ねる。
- 「次の問題へ」ボタンは、「答えを確認する」を押す前に押せるが、押した後も引き続き押せる（どちらの状態でも有効）と仮定する。
- ダミー生成で 10〜30% のランダム差分を使う場合、複数回の実行で選択肢が変わる。これは許容する（シード固定は不要）。
